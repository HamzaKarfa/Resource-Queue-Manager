# v1.1 development: Home Assistant capacity configuration

**Unreleased development branch.** This PR depends on the weighted-policy foundation and is not a release.

## Setup and options

From Settings → Devices & services → Resource Queue Manager:

1. Choose a scheduling strategy independently: FIFO, LIFO or Priority FIFO.
2. Select capacity mode: Classic (default, 1-50 slots) or Weighted (1-100000 shared integer units, no second slot limit).
3. Choose the capacity and supervised Home Assistant entities.
4. Weighted mode displays one native numeric default-weight field per supervised entity, initially 1.
5. Strategy-specific settings are handled in their own separate form.

Existing queues without a capacity mode remain Classic, and old service calls remain compatible.

## Weighted request example

Given a weighted queue with total capacity 100 and a default weight of 30 units for the living-room entity:

    action: resource_queue_manager.request
    data:
      config_entry_id: YOUR_CONFIG_ENTRY_ID
      resource_id: heater_living_room
      entity_id: light.heater_living_room

For a one-request override of 25 units:

    action: resource_queue_manager.request
    data:
      config_entry_id: YOUR_CONFIG_ENTRY_ID
      resource_id: heater_living_room
      entity_id: light.heater_living_room
      engine_data:
        weight: 25

A request's effective weight is frozen while waiting, active, and after restart. An otherwise identical repeated request that omits an override retains its previous frozen weight. Explicit attempts to change existing weights fail. Invalid and unknown provider fields are rejected.

Classic accepts no nonempty engine_data. A pending request consumes no units; only active reservations consume capacity. If the first pending request does not fit, later requests cannot skip it.

A queue cannot switch capacity mode with active or pending requests. Its unit budget cannot be reduced below committed active usage or a pending request's frozen weight. Every reload starts paused and requires explicit resume.

## Scope

This PR supplies Home Assistant configuration and request-service plumbing. It preserves the four existing sensor IDs: in weighted mode, the available sensor reports remaining **units**, not free slot count; all four sensors expose capacity_mode, capacity_total, capacity_used, capacity_remaining and effective_weights attributes. A positive unit remainder does not mean the head of a waiting queue can fit. New sensor entities, grant event metadata and occurrence counters remain separate tracked steps. Resource Queue Manager never switches physical equipment directly.

Run core and Home Assistant integration tests before merge, and test on noncritical entities before adoption.
