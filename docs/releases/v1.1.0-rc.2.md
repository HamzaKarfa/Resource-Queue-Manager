# Resource Queue Manager — v1.1.0-rc.2

**Pré-release / Release candidate — pour essais sur Home Assistant. La v1.0.0 stable reste inchangée.**

Cette préversion inclut toutes les fonctionnalités de `v1.1.0-rc.1` (files indépendantes, capacité pondérée, poids par entité, overrides, récurrences, reprise sécurisée) avec deux améliorations importantes.

## 1. Nouvelle stratégie d'attribution Strict / Backfill

La file dispose d'une **politique d'attribution** indépendante du mode de capacité et de la stratégie d'ordonnancement.

- **Strict** (défaut et comportement historique) : une demande en tête qui ne rentre pas bloque celles derrière.
- **Backfill** : le moteur peut attribuer les ressources suivantes dont les poids rentrent dans les unités disponibles. Les demandes bloquées conservent leur ordre, leurs priorités et leurs récurrences. Aucune réservation active n'est préemptée.

Exemple : capacité 15 ; la ressource A utilise 10 unités ; B (10 unités) attend ; C (3 unités) et D (2 unités) attendent derrière. Le mode Backfill peut attribuer C et D sans déplacer B, alors que Strict les laisse attendre.

**Attention :** sous une forte charge, une grosse demande peut attendre longtemps si des petites demandes continuent d'arriver. Backfill n'implémente pas de vieillissement automatique des priorités ni de réservation anticipée de capacité.

## 2. Configuration Home Assistant organisée en quatre rubriques

Le bouton **Configurer** n'ouvre plus un formulaire géant. Il affiche un menu :

1. **Ressources supervisées** : choisir les entités et leurs poids par défaut en mode pondéré.
2. **Capacité** : Classique/Pondéré et limite de places/unités.
3. **Ordonnancement et attribution** : FIFO, LIFO ou FIFO prioritaire ; Strict ou Backfill. Le formulaire des paramètres de priorité ne s'affiche que lorsqu'il est nécessaire ou demandé.
4. **Demandes répétées** : Ignorer/Compter.

La première installation suit également un assistant guidé pour la sélection des ressources, la capacité, la stratégie, les répétitions et les poids éventuels.

**Préservation des réglages :** éditer une catégorie ne modifie pas les autres. Ouvrir le menu et naviguer n'interrompt pas la file. Les modifications réelles utilisent le rechargement existant, qui laisse la file en `paused` jusqu'au `resume` explicite. Les changements de politique susceptibles d'affecter les réservations restent bloqués tant que la file n'est pas vide.

## Compatibilité

- Toutes les files existantes sans `allocation_mode` restent en **Strict**.
- FIFO, LIFO, Priority FIFO, capacité Classique/Pondéré, comptage des récurrences, `strategy_data`, `engine_data.weight`, services `request/release/cancel/resume`, capteurs et événements conservent leurs contrats.
- Les sauvegardes/restaurations, poids gelés et règles OFF de supervision restent inchangés.
- Les descriptions de configuration sont disponibles en français et en anglais.

## Installation et validation

Cette préversion sert à des tests Home Assistant **2026.11+**. Sauvegarder la configuration et les fichiers `.storage` avant tout essai ; de préférence, utiliser une instance séparée avec des entités sans risque. Vérifier les listes de ressources actives/en attente, les nouveaux modes, puis le retour à `paused` lors d'un rechargement. Se référer au [guide de migration](../MIGRATION_v1.0_to_v1.1.md), à la [documentation Backfill](../V1.2_BACKFILL.md) et aux [nouveaux écrans](../CONFIGURATION_UI_v1.1-rc2.md).

**Retour arrière :** restaurer une sauvegarde cohérente (version du code, configuration et snapshots), plutôt que de redescendre le code seul après création de réservations dans le nouveau mode.

Les validations automatisées ne remplacent pas les vérifications manuelles sur Home Assistant. Aucune fusion dans `main` et aucune publication de la version stable `v1.1.0` ne sont effectuées par cette pré-release.
