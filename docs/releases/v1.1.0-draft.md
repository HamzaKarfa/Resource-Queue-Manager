# Resource Queue Manager v1.1.0 — Draft release notes

**Status: UNRELEASED / approval required.** This is a proposed changelog for maintainers, not an announcement of a published release.

## What's new

- **Capacity providers:** Classic (slot count, default) and Weighted (shared positive integer unit budget, no additional active slot limit).
- **Default entity weights:** native numeric configuration for each supervised `entity_id`, initially 1.
- **Per-request override:** optional `engine_data.weight`; frozen for the request lifetime including restart, independent of scheduling priority.
- **Recurrence counting:** `ignore` by default; optional `count` records repeated waiting requests under a single `resource_id`.
- **Automation observability:** per-queue sensors retain their four entity IDs and expose `capacity_mode`, `capacity_unit`, `capacity_total`, `capacity_used`, `capacity_remaining`, `effective_weights`, `recurrence_mode` and `occurrence_counts`. Grant events additionally carry `capacity_mode`, `effective_weight` and `occurrences`.
- **State durability:** migration of old classic/ignore snapshots, paused recovery, fail-closed corrupted-state handling and no premature grant events on save failure.

## Unchanged

- FIFO, LIFO and Priority FIFO (including priority metadata) are independent and non-preemptive.
- Original `request`/`release`/`cancel`/`resume` actions, `config_entry_id` routing, ON/OFF supervision and old classic configuration.
- No direct physical equipment control, automatic priority boosting, queue-wide power calculation, text-content deduplication, multi-job execution, or global capacity across multiple entries.

## Migration

Read `docs/MIGRATION_v1.0_to_v1.1.md` and take a full backup before deployment. A downgrade to v1.0 from weighted/count snapshots requires restoring the corresponding backup, not simply replacing component code.

## Publication checklist

See `docs/RELEASE_CHECKLIST_v1.1.md`. Validate the **final commit** and explicit maintainer approval. Before actual release, update `manifest.json` to `1.1.0`, follow guarded publishing rules and tag `v1.1.0`. None of these release actions are performed by this draft.
